# Паспорт модели сегментации глиомы

## 1. Общие сведения

| Поле | Значение |
| --- | --- |
| Наименование модели | Модель сегментации глиомы по МРТ головного мозга |
| Назначение | Автоматическая многоклассовая сегментация опухолевых областей на 3D МРТ-исследованиях |
| Тип задачи | Семантическая сегментация медицинских изображений |
| Архитектура | 3D U-Net / BratsUNet |
| Формат артефакта | `model.pth` |
| Статус | Учебный прототип |
| Область применения | Демонстрация ИИ-сервиса для анализа МРТ и интеграции с веб-интерфейсом / DICOM-контуром |
| Ограничение | Не предназначена для клинической диагностики без дополнительной валидации и сертификации |

## 2. Назначение модели

Модель предназначена для автоматического выделения областей глиомы на многомодальных МРТ-изображениях головного мозга. Результатом работы модели является 3D-маска, в которой каждому вокселю присваивается класс ткани или фон.

Модель используется в составе учебного ИИ-сервиса:

```text
NIfTI-модальности -> предобработка -> 3D U-Net -> маска сегментации -> метрики / PNG / DICOM-экспорт
```

## 3. Входные данные модели

Модель принимает четыре МРТ-модальности одного исследования:

| Канал | Модальность | Описание |
| --- | --- | --- |
| 1 | `t1` | T1-взвешенное изображение |
| 2 | `t1ce` | T1-взвешенное изображение с контрастированием |
| 3 | `t2` | T2-взвешенное изображение |
| 4 | `flair` | T2-FLAIR изображение |

Основной файловый формат входа в сервис:

- `.nii`;
- `.nii.gz`.

Ожидаемый формат тензора после предобработки:

```text
[B, C, D, H, W]
```

где:

- `B` — размер batch;
- `C = 4` — число модальностей;
- `D` — число используемых срезов;
- `H`, `W` — высота и ширина изображения после изменения размера.

В учебной конфигурации использовалась предобработка с приведением изображений к размеру `128 x 128` и использованием 96 информативных срезов.

## 4. Выходные данные модели

Модель возвращает многоканальный тензор логитов:

```text
[B, num_classes, D, H, W]
```

После применения `softmax` и `argmax` формируется итоговая маска:

```text
[B, D, H, W]
```

Классы маски:

| Класс | Описание |
| --- | --- |
| `0` | Фон / отсутствие опухолевой ткани |
| `1` | Некротическое и неконтрастирующее ядро опухоли |
| `2` | Перитуморальный отёк |
| `3` | Контрастирующая опухоль; соответствует исходной метке `4` в BraTS |

## 5. Обучающие данные

| Поле | Значение |
| --- | --- |
| Набор данных | BraTS 2020 / Brain Tumor Segmentation Challenge |
| Тип данных | Многомодальные предоперационные МРТ-исследования головного мозга |
| Формат изображений | NIfTI |
| Модальности | T1, T1ce, T2, FLAIR |
| Разметка | Экспертные 3D-маски опухолевых областей |
| Задача | Многоклассовая сегментация глиомы |

В исходном наборе BraTS используются метки `0`, `1`, `2`, `4`. Для обучения в проекте метка `4` приводится к классу `3`, чтобы получить последовательную индексацию классов `0..3`.

## 6. Предобработка

Перед подачей в модель выполняются следующие этапы:

1. Чтение NIfTI-файлов через библиотеку для работы с медицинскими изображениями.
2. Проверка наличия обязательных модальностей.
3. Min-Max нормализация интенсивностей.
4. Обрезка неинформативных срезов.
5. Изменение размера срезов до `128 x 128`.
6. Объединение четырёх модальностей в многоканальный 3D-тензор.
7. Приведение маски к классам `0`, `1`, `2`, `3`.
8. Преобразование эталонной маски в one-hot encoding при расчёте функции потерь.

## 7. Архитектура

Модель реализована как 3D U-Net и состоит из следующих блоков:

| Блок | Назначение |
| --- | --- |
| `DoubleConv` | Две последовательные 3D-свёртки с нормализацией и ReLU |
| `EncoderBlock` | Извлечение признаков и уменьшение пространственного разрешения |
| `Bottleneck` | Центральный блок сети с максимальным числом каналов |
| `DecoderBlock` | Восстановление пространственного разрешения и объединение со skip-связями |
| `Output Conv3d` | Преобразование признаков в логиты классов |

Особенности архитектуры:

- используются 3D-свёртки, так как входные данные являются объёмными;
- применяются skip-соединения между encoder и decoder;
- используется групповая нормализация, более устойчивая при малом batch size;
- выходной слой формирует `num_classes = 4` канала.

Обобщённая структура:

| Уровень | Модуль | Входные каналы | Выходные каналы |
| --- | --- | --- | --- |
| Encoder 1 | EncoderBlock | `in_channels` | `N` |
| Encoder 2 | EncoderBlock | `N` | `2N` |
| Encoder 3 | EncoderBlock | `2N` | `4N` |
| Encoder 4 | EncoderBlock | `4N` | `8N` |
| Bottleneck | DoubleConv | `8N` | `16N` |
| Decoder 1 | DecoderBlock | `16N + 8N` | `8N` |
| Decoder 2 | DecoderBlock | `8N + 4N` | `4N` |
| Decoder 3 | DecoderBlock | `4N + 2N` | `2N` |
| Decoder 4 | DecoderBlock | `2N + N` | `N` |
| Output | Conv3d 1x1x1 | `N` | `4` |

## 8. Обучение

| Параметр | Значение |
| --- | --- |
| Framework | PyTorch |
| Training framework | PyTorch Lightning |
| Оптимизатор | Adam |
| Функция потерь | Dice Loss + Cross-Entropy Loss |
| Логирование | TensorBoard |
| Сохранение лучшей модели | ModelCheckpoint |
| Защита от переобучения | EarlyStopping |
| Основная метрика валидации | Dice |

Функция потерь объединяет преимущества Dice Loss и Cross-Entropy Loss:

- Dice Loss учитывает перекрытие предсказанной и истинной маски и лучше подходит для несбалансированных классов;
- Cross-Entropy Loss стабилизирует пиксельную/воксельную классификацию.

## 9. Эксперименты и гиперпараметры

В ходе учебного эксперимента сравнивались разные значения:

- learning rate;
- количество эпох;
- базовое число каналов `n_channels`.

Пример зафиксированной лучшей конфигурации из учебного эксперимента:

| Параметр | Значение |
| --- | --- |
| Learning rate | `0.001` |
| Количество эпох | `30` |
| `n_channels` | `16` |
| Dice | `0.5964` |
| Loss | `0.5751` |

Значения являются результатами учебного эксперимента и требуют повторной проверки при изменении данных, предобработки, версии кода или вычислительной среды.

## 10. Метрики качества

Для оценки модели используются:

| Метрика | Назначение |
| --- | --- |
| Dice | Основная метрика перекрытия масок |
| Dice по классам | Анализ качества по отдельным опухолевым областям |
| IoU / Jaccard | Дополнительная метрика перекрытия |
| Loss | Контроль обучения и валидации |
| Время инференса | Техническая метрика производительности сервиса |

Для полноценной приёмки модели необходимо хранить:

- `test_metrics.json`;
- `test_metrics.csv`;
- Dice по каждому классу;
- примеры предсказаний;
- версию модели;
- checksum артефакта;
- дату обучения;
- параметры предобработки.

## 11. Инференс

Этапы инференса:

1. Получить четыре NIfTI-модальности.
2. Выполнить ту же предобработку, что и при обучении.
3. Сформировать тензор `[B, 4, D, H, W]`.
4. Загрузить `model.pth`.
5. Выполнить forward pass.
6. Применить `softmax` по классовой оси.
7. Применить `argmax` для получения итоговой маски.
8. Сохранить маску и метрики.
9. Сформировать PNG-срезы и overlay для веб-интерфейса.

## 13. Ограничения модели

- Модель обучена на BraTS-подобных данных и может плохо переноситься на данные с другим протоколом съёмки.
- Модель ожидает наличие четырёх модальностей `t1`, `t1ce`, `t2`, `flair`.
- Модель чувствительна к несогласованности ориентации, размера и пространственного соответствия модальностей.
- Модель не должна использоваться как единственный источник клинического решения.
- Для реального медицинского применения необходима внешняя клиническая валидация.
- Возможны ошибки на малых опухолевых областях, размытых границах и данных с артефактами.
- Текущая реализация ориентирована на учебный MVP, а не на промышленную эксплуатацию.

## 14. Риски

| Риск | Последствие | Меры снижения |
| --- | --- | --- |
| Неверная сегментация | Ошибка интерпретации результата | Использовать только как подсказку, проводить врачебную проверку |
| Несовместимый формат входа | Ошибка инференса | Валидация входных файлов и статусы `failed` |
| Отличие реальных данных от BraTS | Снижение качества | Внешняя валидация и дообучение |
| Ошибка предобработки | Некорректная маска | Фиксация preprocessing config и тесты |
| Смена версии модели без проверки | Регресс качества | Регресс-тест на эталонном наборе |
| Потеря артефакта | Невозможность воспроизвести результат | Хранение checksum и версионирование |

## 15. Требования к обновлению версии

При обновлении модели необходимо:

1. Обновить `model.pth`.
2. Зафиксировать версию модели.
3. Обновить checksum артефакта.
4. Запустить инференс на эталонном тестовом наборе.
5. Сравнить Dice и IoU с предыдущей версией.
6. Проверить, что REST API и worker корректно загружают новую модель.
7. Проверить визуализации PNG и overlay.
8. Проверить DICOM-экспорт после обработки.
9. Обновить паспорт модели.
10. Зафиксировать результат регресс-теста.

## 16. Критерии готовности модели для MVP

| № | Критерий | Статус проверки |
| --- | --- | --- |
| 1 | Модель принимает 4 NIfTI-модальности | Должно проверяться функциональным тестом |
| 2 | Модель формирует 3D-маску с 4 классами | Должно проверяться инференсом на тестовом кейсе |
| 3 | Модель интегрирована в worker | Должно проверяться через Kafka-задачу |
| 4 | Результат сохраняется в S3 | Должно проверяться после обработки |
| 5 | Метрики рассчитываются при наличии `true_mask` | Должно проверяться тестовым кейсом с маской |
| 6 | PNG-срезы доступны через API | Должно проверяться frontend/backend тестом |
| 7 | Ошибка инференса не останавливает сервис | Должно проверяться негативным тестом |
| 8 | Версия и ограничения модели описаны | Выполнено в данном паспорте |
